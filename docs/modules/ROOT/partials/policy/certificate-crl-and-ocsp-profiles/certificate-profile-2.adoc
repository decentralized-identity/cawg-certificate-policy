[[certificate-profile-2]]
=== Certificate profile

The <<certification-authority,CA>> MUST meet the technical requirements set forth in <<publication>>, <<key-sizes>>, and <<public-key-parameters-generation-and-quality-checking>>.

<<certification-authority,CAs>> MUST generate non-sequential <<certificate,certificate>> serial numbers greater than zero (0) and less than 2^159 containing at least 64 bits of output from a <<cryptographically-secure-pseudo-random-number-generator,CSPRNG>>.

[[certificate-profile-version-numbers]]
==== Version number(s)

<<certificate,Certificates>> MUST be of type X.509 v3.

[[certificate-content-and-extensions-application-of-rfc-6818]]
==== Certificate content and extensions; application of RFC 6818

This section specifies the additional requirements for <<certificate,certificate>> content and extensions for <<certificate,certificates>>.

[[certificate-content-and-extensions-root-ca-certificates]]
===== Root CA certificates

. `basicConstraints` (MUST be present)
+
This extension MUST be marked critical.
The `cA` field MUST be set `true`.
The `pathLenConstraint` field SHOULD NOT be present.

. `keyUsage` (MUST be present)
+
This extension MUST be marked critical.
Bit positions for `keyCertSign` and `cRLSign` MUST be set.
If the <<root-certification-authority,root CA>> <<private-key,private key>> is used for signing <<online-certificate-status-protocol,OCSP>> responses, then the `digitalSignature` bit MUST be set.

. `certificatePolicies` (SHOULD NOT be present)
+
This extension SHOULD NOT be present.

. `extKeyUsage` (MUST NOT be present)
+
This extension MUST NOT be present.

. `subjectKeyIdentifier` (MUST be present)
+
This extension MUST NOT be marked critical.
It MUST contain a value that is included in the `keyIdentifier` field of the `authorityKeyIdentifier` extension in <<certificate,certificates>> issued by the <<root-certification-authority,root CA>>.

[[certificate-content-and-extensions-subordinate-ca-certificates]]
===== Subordinate CA certificates

. `certificatePolicies` (MUST be present)
+
This extension SHOULD NOT be marked critical.
+
All ``policyIdentifier``s included in this extension MUST be included in accordance with <<certificate-content-and-extensions-subordinate-ca-certificates>>.
+
If the value of this extension includes a `PolicyInformation` which contains a qualifier of type `id-qt-cps` (<<object-identifier,OID>>: 1.3.6.1.5.5.7.2.1), then the value of the qualifier MUST be a HTTP or HTTPS URL for the <<issuing-ca,issuing CA>>’s <<certificate-policy,CP>> and/<<certification-practice-statement,or CPS>>, <<relying-party,relying party>> Agreement, or other pointer to online policy information provided by the <<issuing-ca,issuing CA>>.
If a qualifier of type `id-qt-unotice` (<<object-identifier,OID>>: 1.3.6.1.5.5.7.2.2) is included, then it MUST contain `explicitText` and MUST NOT contain `noticeRef`.

. `cRLDistributionPoints` (MUST be present)
+
This extension MUST NOT be marked critical.
It MUST contain the HTTP URL of the <<certification-authority,CA>>’s <<certificate-revocation-list,CRL>> service.

. `authorityInformationAccess` (SHOULD be present)
+
This extension MUST NOT be marked critical.
+
It SHOULD contain the HTTP URL of the <<issuing-ca,issuing CA>> <<certificate,certificate>> (`accessMethod` = 1.3.6.1.5.5.7.48.2).
It MAY contain the HTTP URL of the <<issuing-ca,issuing CA>> <<online-certificate-status-protocol,OCSP>> responder (`accessMethod` = 1.3.6.1.5.5.7.48.1).

. `basicConstraints` (MUST be present)
+
This extension MUST be marked critical.
The `cA` field MUST be set `true`.
The `pathLenConstraint` field MAY be present.

. `keyUsage` (MUST be present)
+
This extension MUST be marked critical.
Bit positions for `keyCertSign` and `cRLSign` MUST be set.
If the <<subordinate-ca,subordinate CA>> <<private-key,private key>> is used for signing <<online-certificate-status-protocol,OCSP>> responses, then the `digitalSignature` bit MUST be set.

. `nameConstraints` (MAY be present)
+
This extension SHOULD be marked critical.
+
NOTE: Non-critical name constraints are an exception to https://datatracker.ietf.org/doc/html/rfc5280#section-4.2.1.10[RFC 5280 §4.2.1.10]; however, they MAY be used until the `nameConstraints` extension is supported by application software suppliers whose software is used by a substantial portion of relying parties worldwide.

. `extKeyUsage` (MAY be present for <<cross-certificate,cross certificates>>; MUST be present otherwise)
+
For <<cross-certificate,cross certificates>> that share a <<subject,subject>> <<distinguished-name,distinguished name>> and <<subject,subject>> <<public-key,public key>> with a <<root-certification-authority-certificate,root CA certificate>> operated in accordance with these requirements, this extension MAY be present.
If present, this extension SHOULD NOT be marked critical.
This extension MUST only contain usages for which the <<issuing-ca,issuing CA>> has verified the <<cross-certificate,cross certificate>> is authorized to assert.
This extension MUST NOT contain the `anyExtendedKeyUsage` usage.
+
For all other <<subordinate-ca,subordinate CA>> <<certificate,certificates>>, including <<technically-constrained-subordinate-ca-certificate,technically-constrained subordinate CA certificates>>, this extension MUST be present and SHOULD NOT be marked critical.
+
NOTE: While https://datatracker.ietf.org/doc/html/rfc5280#section-4.2.1.12[RFC 5280 §4.2.1.12] notes that this extension will generally only appear within end-entity certificates, these requirements make use of this extension to further protect relying parties by limiting the scope of subordinate certificates, as implemented by a number of application software suppliers.
+
For <<subordinate-ca,subordinate CA>> <<certificate,certificates>> that will be used to issue S/MIME <<certificate,certificates>>, the value `id-kp-emailProtection` MUST be present.
The values `id-kp-serverAuth`, `id-kp-codeSigning`, `id-kp-timeStamping`, and `anyExtendedKeyUsage` MUST NOT be present.
Other values MAY be present.

. `authorityKeyIdentifier` (MUST be present)
+
This extension MUST NOT be marked critical.
It MUST contain a `keyIdentifier` field and it MUST NOT contain a `authorityCertIssuer` or `authorityCertSerialNumber` field.

. `subjectKeyIdentifier` (MUST be present)
+
This extension MUST NOT be marked critical.
It MUST contain a value that is included in the `keyIdentifier` field of the `authorityKeyIdentifier` extension in <<certificate,certificates>> issued by the <<subordinate-ca,subordinate CA>>.

[[all-certificates]]
===== All certificates

All fields and extensions MUST be set in accordance with https://datatracker.ietf.org/doc/html/rfc5280[RFC 5280].
The <<certification-authority,CA>> MUST NOT issue a <<certificate,certificate>> that contains a `keyUsage` flag, `extKeyUsage` value, <<certificate,certificate>> extension, or other data not specified in <<certificate-content-and-extensions-root-ca-certificates>>, <<certificate-content-and-extensions-subordinate-ca-certificates>>, or <<certificate-content-and-extensions-subscriber-certificates>> unless the <<certification-authority,CA>> is aware of a reason for including the data in the <<certificate,certificate>>.
If the <<certification-authority,CA>> includes fields or extensions in a <<certificate,certificate>> that are not specified but are otherwise permitted by these requirements, then the <<certification-authority,CA>> MUST document the processes and procedures that the <<certification-authority,CA>> employs for the validation of information contained in such fields and extensions in its <<certificate-policy,CP>> and/<<certification-practice-statement,or CPS>>.

<<certification-authority,CAs>> MUST NOT issue a <<certificate,certificate>> with:

. Extensions that do not apply in the context of the public Internet (such as an `extKeyUsage` value for a service that is only valid in the context of a privately managed network), unless:

.. such value falls within an <<object-identifier,OID>> arc for which the <<applicant,applicant>> demonstrates ownership, or
.. the <<applicant,applicant>> can otherwise demonstrate the right to assert the data in a public context; or
.. the extension is defined within an open standards specification and intended for use by other organizations.
A <<certificate,certificate>> that includes such an extension MUST conform to the specifications of the open standard and of these requirements.

. Field or extension values which have not been validated according to the processes and procedures described in these requirements or the <<certification-authority,CA>>’s <<certificate-policy,CP>> and/<<certification-practice-statement,or CPS>>.

[[algorithm-object-identifiers]]
==== Algorithm object identifiers

[[subjectpublickeyinfo]]
===== Subjectpublickeyinfo

The following requirements apply to the `subjectPublicKeyInfo` field within a <<certificate,certificate>>.
No other encodings are permitted.

[[certificate-profile-algorithm-object-identifiers-subjectpublickeyinfo-rsa]]
====== RSA

The <<certification-authority,CA>> MUST indicate an RSA key using the `rsaEncryption` (<<object-identifier,OID>>: 1.2.840.113549.1.1.1) algorithm identifier.
The parameters MUST be present, and MUST be an explicit `NULL`.

The <<certification-authority,CA>> MUST NOT use a different algorithm, such as the `id-RSASSA-PSS (<<object-identifier,OID>>: 1.2.840.113549.1.1.10) algorithm identifier, to indicate an RSA key.

When encoded, the `AlgorithmIdentifier` for RSA keys MUST be byte-for-byte identical with the following hex-encoded bytes: `300d06092a864886f70d0101010500`

Effective 15 September 2026 the <<certification-authority,CA>> MUST NOT sign a certificate using a signature algorithm that incorporates SHA-1.

Prior to 15 September 2026 the <<certification-authority,CA>> MUST revoke any unexpired <<subordinate-ca,subordinate CA>> <<certificate,certificate>> whose signature algorithm incorporates SHA-1.

====
Date-specific limitations are a likely holdover from S/MIME. Consider removing.

[[certificate-profile-algorithm-object-identifiers-subjectpublickeyinfo-ecdsa]]
====== ECDSA

The <<certification-authority,CA>> MUST indicate an ECDSA key using the `id-ecPublicKey` (<<object-identifier,OID>>: 1.2.840.10045.2.1) algorithm identifier.
The parameters MUST use the `namedCurve` encoding.

* For P-256 keys, the `namedCurve` MUST be `secp256r1` (<<object-identifier,OID>>: 1.2.840.10045.3.1.7).
* For P-384 keys, the `namedCurve` MUST be `secp384r1` (<<object-identifier,OID>>: 1.3.132.0.34).
* For P-521 keys, the `namedCurve` MUST be `secp521r1` (<<object-identifier,OID>>: 1.3.132.0.35).

When encoded, the `AlgorithmIdentifier` for ECDSA keys MUST be byte-for-byte identical with the following hex-encoded bytes:

* For P-256 keys, `301306072a8648ce3d020106082a8648ce3d030107`.
* For P-384 keys, `301006072a8648ce3d020106052b81040022`.
* For P-521 keys, `301006072a8648ce3d020106052b81040023`.

[[certificate-profile-algorithm-object-identifiers-subjectpublickeyinfo-eddsa]]
====== EdDSA

The <<certification-authority,CA>> MUST indicate an EdDSA key using one of the following algorithm identifiers below:

* For Curve25519 keys, the `algorithm` MUST be `id-Ed25519` (<<object-identifier,OID>>: 1.3.101.112).
* For Curve448 keys, the `algorithm` MUST be `id-Ed448` (<<object-identifier,OID>>: 1.3.101.113).

The parameters for EdDSA keys MUST be absent.

When encoded, the `AlgorithmIdentifier` for EdDSA keys MUST be byte-for-byte identical with the following hex-encoded bytes:

* For Curve25519 keys, `300506032b6570`.
* For Curve448 keys, `300506032b6571`.

[[signature-algorithmidentifier]]
===== Signature `AlgorithmIdentifier`

All objects signed by a <<certification-authority,CA>> <<private-key,private key>> MUST conform to these requirements on the use of the `AlgorithmIdentifier` or `AlgorithmIdentifier`-derived type in the context of signatures.

In particular, it applies to all of the following objects and fields:

* the `signatureAlgorithm` field of a <<certificate,certificate>>,
* the `signature` field of a `TBSCertificate` (for example, as used by a <<certificate,certificate>>),
* the `signatureAlgorithm` field of a `CertificateList`,
* the `signature` field of a `TBSCertList`, and
* the `signatureAlgorithm` field of a `BasicOCSPResponse`.

No other encodings are permitted for these fields.

[[certificate-profile-algorithm-object-identifiers-signature-algorithmidentifier-ecdsa]]
====== ECDSA

The <<certification-authority,CA>> MUST use the appropriate signature algorithm and encoding based upon the signing key used.

If the signing key is P-256, the signature MUST use ECDSA with SHA-256.

. MUST NOT contain the `anyPolicy` identifier (2.5.29.32.0).

A <<certificate,certificate>> issued to a <<subordinate-ca,subordinate CA>> that is an <<affiliate,affiliate>> of the <<issuing-ca,issuing CA>> MUST include a set of policy identifiers from one of the two options below:

. One or more explicit policy identifiers defined in <<reserved-certificate-policy-identifiers>>, that indicate the <<subordinate-ca,subordinate CA>>’s adherence to and compliance with these requirements and MAY contain one or more identifiers documented by the <<subordinate-ca,subordinate CA>> in its <<certificate-policy,CP>> and/or <<certification-practice-statement,CPS>>; or
. The `anyPolicy` identifier (2.5.29.32.0).

The <<subordinate-ca,subordinate CA>> and the <<issuing-ca,issuing CA>> MUST represent, in their <<certificate-policy,CP>> and/<<certification-practice-statement,or CPS>>, that all <<certificate,certificates>> containing a policy identifier indicating compliance with these requirements are issued and managed in accordance with these requirements.

[[certificate-policy-object-identifier-subscriber-certificates]]
===== Subscriber certificates

A <<certificate,certificate>> issued to a <<subscriber,subscriber>> MUST contain, within the <<certificate,certificate>>’s `certificatePolicies` extension, a policy identifier that is specified in <<reserved-certificate-policy-identifiers>>.

The <<certificate,certificate>> MAY also contain additional policy identifier(s) documented by the <<issuing-ca,issuing CA>> in its <<certificate-policy,CP>> and/<<certification-practice-statement,or CPS>>.
